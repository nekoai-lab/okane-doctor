# 画面仕様（v2.0）

| 画面 | 主要要素 | 主要操作 | 必須状態 | データ |
|---|---|---|---|---|
| ホーム | 中立性説明、C系家族ヒーロー、診断CTA | 診断開始 | 未診断/途中再開（実装時） | 診断の有無 |
| 条件入力 | 質問・回答・ヘルプ・進捗 | 選択/戻る/次へ | 選択中/未回答/検証エラー/再開 | 既存計算エンジンの入力型 |
| 診断サマリー | 必要額、判定、年齢推移、試算前提 | もしもラボへ/詳細 | 試算済/未算定/再計算中 | エンジンの出力 |
| もしもラボ | 医療/休職6項目と死亡保障を分離、年齢変更 | シナリオ詳細/年齢変更 | 試算済/未算定/読み込み中 | 7シナリオの出力・時系列 |
| シナリオ詳細 | 負担額・判定・算定前提 | 戻る/前提開閉 | 数値あり/未算定/根拠不足 | シナリオ単位の結果 |
| 診断履歴・比較 | 日付・条件版・保存データ | 開く/比較/再診断 | 空/履歴あり/保存失敗 | 保存機能の実装後のみ |
| ガイド | 判定の意味、計算の前提、FAQ | 展開/関連画面へ | 通常 | 静的な説明と計算仕様 |

## 情報設計の原則
- 初見の利用者には「問い→結果の意味→確認すること」の順。
- シナリオ一覧は全体像を先に示すが、死亡と医療/休職の金額を一つのランキングとして表現しない。
- 「不足の可能性」や「要精査」は購入を促すCTAにしない。
- 未算定は0円として表示しない。
- 結果画面で内訳や控除内容がエンジンから得られない場合、AIが補完しない。
- グラフの数値比例・比較可能性・凡例の理解容易性をQAする。

## フォームの注意
試作品は代表項目の見た目だけを扱う。実装では `app/lab/page.tsx` の復元パラメータと現行入力スキーマを照合し、質問を勝手に削減しない。

## イラストの出し分け
属性を確定できる場合のみ、その人物の画像を選ぶ。属性未確定では風景または抽象イメージを使う。家族構成は画像から推測しない。ヒーローは文字なし画像＋HTMLテキストを基本とする。
