# もしもラボ｜イラスト運用ガイド v1.0

> ステータス：デザイン方針確定／実装用ルール草案（2026-10-17）  
> 対象：もしもラボを含む診断アプリ全体、スマホ390pxを基準

## 1. 基本方針

- **UI：Modern Fintech A**。白を基調に、濃紺の文字、明快なブルーの操作要素。装飾より情報・数値・操作性を優先。
- **イラスト：家族パターンC**。透明感のある青空と水辺、自然光、爽やかな新緑、柔らかなアニメ調の人物表現。親しみやすいが幼くしない。
- **固定する世界観**：日本の都市近郊の暮らし、明るい自然光、ブルー・グリーン・白・淡いベージュ、自然な会話と表情、年齢に応じた等身。
- **対象人物**：①家族4人（大人2人＋子ども2人）、②シニア（単身・2人世帯も想定）、③若い単身男性、④若い単身女性。将来的に多様な家族形態へ拡張可能にする。
- **中立性**：不安を煽る、病気・死を直接描く、商品名や申込訴求を入れることは禁止。特定の家族像や性別役割を唯一の標準として固定しない。
- **計算結果は別系統**：イラストに金額・判定・グラフ・UI文字列を焼き込まない。金額・判定は計算エンジンの出力のみ表示する。

## 2. 画面別マッピング

| 画面 | イラスト役割 | シーン／人物 | 配置と注意点 |
|---|---|---|---|
| ホーム・初回案内 | ヒーロー | 利用者属性に合う4系統の人物（未選択時は人物を固定しない中立カットも用意） | ファーストビューで1点。見出し・CTAを隠さない。家族なら4人を近い距離で同じ場面に置く |
| 家族構成の入力 | 補助 | 4人家族／単身／シニアの小カット | 選択カードに使う場合は同サイズ・同視点で比較。選択はテキストでも識別可能に |
| 年齢・年収・資産などの入力 | 原則なし | 必要なら小さな情景カット | 入力とラベルが主役。装飾が長いフォームを押し下げない |
| 診断結果サマリー | なくても成立 | 使用するなら控えめな人物カット | **金額・判定・前提条件が最優先**。不安や緊張を表す表情は使わない |
| 医療・休職シナリオ | 文脈の補助 | 室内で休む・家で過ごす等の日常シーン | 重篤さの演出、医療恐怖表現を避ける。想定事象を誤認させない |
| 死亡保障のシナリオ | 原則なし | 使う場合は中立的な暮らしの情景 | 故人不在、泣く遺族、暗い演出は使わない |
| 試算グラフ・年齢スライダー | なし | — | 文字とデータ可視化に集中。イラストは不要 |
| 診断結果の見方・ヘルプ | ガイド | 各セグメントの人物が落ち着いて確認する様子 | 安心感と理解の補助。過度に感情的にしない |
| 診断履歴・条件比較 | 原則なし | 空状態のみ小さな汎用カット | 履歴カードと比較情報の可読性を優先 |
| 空状態・完了 | 補助 | 植物・空・机などの汎用カット | 誘導や過剰な祝福を避ける |

**使い分け原則**：画面の主目的が「理解・比較・入力」であるほどイラストを減らす。単身・シニアにも家族4人の画像を一律に表示しない。属性による出し分けは回答済みの情報または明示的な選択に限り、見た目から推定しない。

## 3. アセット制作仕様

- **人物共通設定**：年齢帯、髪型、服装、配色、表情を各キャラクターの参照画像で統一。シーンによって顔立ち・人数を変えない。
- **家族パターンC**：大人2人＋子ども2人。大人の一方だけを大きく／前景に置かない。自然な視線交流、手をつなぐなど相互関係を表現。
- **シニア**：活動的かつ自然。若作りや老いの強調、介護されるイメージへの固定化を避ける。単身版・夫婦版を用意。
- **単身男女**：同等の生活感・自立性・情報量。男性＝仕事、女性＝家事といった画一的役割にしない。
- **背景**：空・水辺・新緑・木漏れ日・明るい室内。背景の主張は控えめにし、余白を確保。色味は青・緑中心で派手な彩度は抑える。
- **必要な納品**：各人物セグメントにつき `hero`（横長）、`card`（4:3）、`spot`（正方形）を用意し、可能なら背景分離版も。画像形式は原本PNG/WebP等と配信用WebP/AVIFを用途に応じて選定。
- **アクセシビリティ**：情報上必須の意味を絵だけで伝えない。装飾画像なら `alt=""`、意味のある画像なら簡潔な代替テキストを付ける。

## 4. UIとの統合ルール

1. 写真風の緻密な絵が画面全体を占領しないよう、UIの白地・紺文字・青い操作要素の強弱を優先。
2. イラストはヒーロー／補助／空状態の3段階に役割を限定し、同じ画面に大きなイラストを重ねない。
3. 390px画面ではタイトル・主要情報・操作が隠れないよう、ヒーローの高さと切り抜きを実機相当で検証。
4. テキストやCTAの下に人物の顔や密な背景を置かない。文字はHTMLとして実装し、画像内へ組み込まない。
5. デザイン変数（文字色、アクセント色、カード背景、余白など）は既存のUIトークンに合わせる。**イラスト案のカラーチップは参考値であり、未検証のHEXを確定トークンにしない**。
6. イラストは決定事項の補強であり、判定や次の行動の根拠には使わない。

## 5. 制作・受け入れチェック

- [ ] 家族／シニア／単身男性／単身女性が同じ絵柄・塗り・光・背景で並ぶ
- [ ] 参照画像と同じ人物として識別できる（顔・髪・服装の一貫性）
- [ ] キャラクターに不必要な主従関係、性別役割、年齢ステレオタイプがない
- [ ] イラストに生成された金額・ラベル・UI文字が入っていない
- [ ] 390px幅で見出し・フォーム・グラフの可読性を妨げない
- [ ] 画像容量、表示速度、レスポンシブの切り抜き、代替テキストを確認
- [ ] 中立的な診断として恐怖訴求・商品販売・加入誘導がない

## 6. 次の実装順

1. 家族C・シニア・単身男女の**参照画像をマスターアセットとして確定**し、可能ならキャラクターの顔アップ／正面・側面を補完する。
2. 各セグメントの hero/card/spot を同じアスペクト比・光源・彩度で制作する。
3. デザインシステムに `Illustration` の使用ルールとファイルパスを追加し、画面コンポーネントから参照する。
4. ホームとヘルプを先行実装し、390px幅で見た目・読みやすさ・端末負荷をレビューする。
5. 結果画面や入力画面は、無理に絵を足さず必要性を確認してから拡張する。
