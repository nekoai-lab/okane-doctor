# Claude Codeへの依頼｜もしもラボ Design Handoff v2.0 レビューとデザイン承認版の作成

## 目的・今回のゴール
添付 `moshimo_design_system_phase2_v2.zip` はChatGPTとユーザーが共同で方向性を決めたレビュー用のデザイン一式。まず現行 `nekoai-lab/okane-doctor` と照合し、スマートフォン390pxで7画面の表示・操作をブラウザで検証したうえで、**修正後プロトタイプ／スクリーンショット／差分報告**を提出すること。**本番アプリへの組み込みは、ユーザーのデザイン承認を受けるまで行わない。**

## 変更不可のデザイン判断
- UI：Modern Fintech A。白・ネイビー・ブルーを基調とする、すっきりした金融UI。WealthNaviは参考イメージであり、その固有表現を複製しない。
- イラスト：先にユーザーが承認した**家族パターンC**がマスター。青空・水辺・新緑・自然光、明るく品のよいタッチ。家族（大人2人＋子ども2人）、シニア、単身男性、単身女性の4系統を使用する。登場人物の顔立ち・衣装・画風・関係性を勝手に変えない。
- 添付ZIP内の画像は**承認済み参照からの暫定切り抜き**。新しい人物イラストを勝手に生成・置換しない。画像が用途に適さない場合は不足アセットとして報告する。
- 商品販売・商品名・申込誘導なし。中立で、不安を煽らず、保険に詳しくない会社員にも理解できる文言にする。
- 金額・判定・計算曲線をUIや生成AIが創作しない。実計算と未接続のプロトタイプでは「レビュー用／入力と数値は非連動」を明示。エンジンへの統合は別フェーズ。

## 作業順序
### A. 現状調査
- 既存リポジトリの構造、CSS/デザインシステム、ルート、型、計算エンジンとの境界を調べる。
- ZIPの内容と現行実装を照合。承認済みデザイン／未承認・暫定要素／不一致点を一覧にする。
- 対象は7画面：ホーム、条件入力、診断サマリー、もしもラボ、シナリオ詳細、診断履歴・比較、結果の見方・ガイド。

### B. ブラウザによるUX/ビジュアル検証
- **390px幅を必須**として、必要に応じ320px/375px/430px/デスクトップでも確認。
- Playwrightなどで画面ごとのフルページ画像と主要状態（選択中、展開、戻る、ナビゲーション）を撮る。実行不能なら理由と再現手順を報告し、検証済みと書かない。
- 横スクロール、画像の不適切な切断、文字の折り返し、数値の単位、ボタンのタップ領域、フォーカス、コントラスト、画面順序、読み込み/空状態、誤タップを点検。
- 特に「もしもラボ」の7シナリオ、医療・休職と死亡保障の異なる算定基準、未算定の明示、概念図と金額比例図の区別を確認。

### C. レビュー用プロトタイプ修正
- 既存本番コードに手を入れず、プロトタイプ側で明確なUIの不具合だけ修正する。
- デザイン判断が必要な箇所は勝手に別案を決めず、現状・代替案・推奨案を記載する。
- 既存画像の人物や画風を変更せずに使い、使いづらいサイズは不足素材として整理する。
- 数値や説明にソース不明の表現を発見したら新規の架空値で埋めず、原典・エンジンに照合する。

### D. 納品と承認ゲート
- 修正版プロトタイプ一式
- 7画面・390pxのスクリーンショット（必要な操作状態を追加）
- `REVIEW_REPORT.md`：重大度、スクリーンショット位置、問題、修正内容、保留事項
- `DESIGN_DECISIONS.md`：確定事項、要ユーザー判断、画像差し替え対象、後工程の課題
- `ASSET_GAPS.md`：本番用の横長画像・カード画像・切り抜き素材などの不足リスト
- `HANDOFF_NEXT.md`：承認後の実装ステップとCodex向け独立QA項目

## 作業上の制約
- `AGENTS.md`、既存のブランチ保護・worktree運用に従う。mainや本番を直接変更しない。
- 作業ブランチを分離する。コミット/PRは既存ルールに従う。
- **初回は調査計画と懸念点を提示**する。ブラウザ検証後、結果を見て修正。レビュー終了時にユーザー承認を求める。
- 計算エンジン、現行実装のルーティング、保存/個人情報処理を変更しない。
- 実装フェーズ開始時はClaude Codeが実装、Codexが独立QA、ChatGPT＋ユーザーがUX/デザイン承認を行う。
